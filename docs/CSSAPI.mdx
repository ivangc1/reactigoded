# CSS API pública

Las clases `.ig-*` son **contrato público** del DS. Documentadas aquí
para consumers que usan reactigoded sin React (HTML estático, Astro,
Hugo, templates server-side, otros frameworks).

## Convenciones

- Todos los selectores empiezan por `.ig-*`.
- Variants semánticas: `brand`, `secondary`, `success`, `warning`, `danger`, `info`.
- Sizes: `sm`, `md` (default, sin clase modificadora), `lg`. Algunos componentes añaden `xs` y `xl`.
- Modificadores se concatenan: `<button class="ig-btn ig-btn-brand ig-btn-sm">…</button>`.
- Estados (`:hover`, `:focus-visible`, `:disabled`) los aplica el navegador o el consumer.
- Algunas clases de variant se construyen dinámicamente — se documentan los patrones (`ig-btn-{variant}`) en lugar de listar las 6 explícitamente.

> **API React polimórfica**: el componente `<Card>` acepta la prop
> `as` para renderear cualquier elemento HTML (`as="article"`,
> `as="a"` con `href`, `as="section"`) o componente
> (`as={Link}` para react-router/next). Las props específicas del
> elemento subyacente se tipan automáticamente vía genéricos TS.
> Las clases CSS son las mismas independientemente de `as`.

## i18n y a11y strings

El DS expone strings user-facing (a11y labels y texto visible mínimo) con **defaults en español** porque la audience inicial — InfiniteRol y consumers hispanohablantes — no necesita configuración para empezar. **No es descuido**: la decisión está registrada y se reevaluará en 1.1.0 si la demanda real lo justifica. Cada componente acepta override por prop o por `aria-label` HTML estándar — la migración i18n para apps anglo o multiidioma es trivial.

### Componentes con override de a11y label

| Componente | Default ES | Prop override |
|---|---|---|
| `Alert` | "Cerrar" | `closeLabel` |
| `Chip` | "Eliminar" | `removeLabel` |
| `ModalClose` | "Cerrar" | `aria-label` (HTML estándar) |
| `Pagination` | "Anterior" / "Siguiente" | `prevLabel`, `nextLabel` |
| `Progress` | "Cargando" / "X por ciento completado" | `loadingLabel`, `formatLabel` |
| `Stepper` | "Progreso" | `aria-label` (HTML estándar) |
| `Toast` | "Cerrar" | `closeLabel` |

### Patrón de uso para apps multiidioma

Usa tu sistema i18n (react-intl, lingui, i18next, etc.) y pasa los strings traducidos como props:

```tsx
import { useTranslation } from "react-i18next";
import { Alert, Pagination } from "@igoded/reactigoded";

function MyAlert() {
  const { t } = useTranslation();
  return <Alert closeLabel={t("common.close")}>Mensaje</Alert>;
}

function MyPager() {
  const { t } = useTranslation();
  return (
    <Pagination
      page={1}
      totalPages={10}
      prevLabel={t("pagination.prev")}
      nextLabel={t("pagination.next")}
      onChange={() => {}}
    />
  );
}
```

Para `Progress` con porcentaje dinámico, usa `formatLabel` (recibe el porcentaje redondeado y devuelve el `aria-label`):

```tsx
<Progress
  value={percent}
  formatLabel={(p) => t("progress.format", { percent: p })}
/>
```

`aria-label` HTML estándar siempre gana sobre cualquier prop dedicada — útil para casos one-off donde no quieres centralizar el string.

## Notas finales

- Los slots compound (`-header`, `-body`, `-footer`, etc.) están pensados para reflejar la jerarquía semántica nativa del HTML; no son obligatorios si construyes un layout custom encima.
- Los componentes con múltiples sub-clases (Sidebar, Card, Modal, Dropdown, Tabs, Navbar, Stepper, Toast, Timeline, Input compound, Table) requieren la composición completa para funcionar visualmente — usar solo la clase wrapper sin los slots produce resultados parciales.
- Estados del navegador (`:hover`, `:focus-visible`, `:disabled`) los aplica el navegador automáticamente cuando los elementos son interactivos. La librería utility-pseudo (`state.css`, opt-in) permite forzar estados desde HTML estático sin depender del estado real del DOM.
